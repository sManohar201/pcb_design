Lesson 11 · High-speed signals

Memory (DDR) routing

A DDR memory bus is the densest timing problem on most boards: dozens of signals that must arrive within a few picoseconds of each other, at hundreds of megabits per second per pin, through a shared address bus that visits every chip. The rules look like a long list, but they all come from three ideas you already know: groups that must arrive together (lesson 8), topology (lesson 7.3) and a timing budget.

On a Jetson carrier board

The LPDDR memory on a Jetson module sits on the module, so you will not route DDR on the carrier board. This lesson is here for completeness, as you asked. The same ideas apply directly to what you will route: PCIe and USB lanes, MIPI CSI clock/data lanes (matched to their clock lane, much like DQ to DQS), and any DDR you add for an FPGA or a second processor.

You'll learn

  • How a DDR bus is split into groups, and which group is matched to which
  • Why matching is done in time, not millimetres, and why a layer change upsets it
  • Why the address bus is a terminated fly-by chain, and how "write leveling" fixes the skew it creates
  • Where the timing budget goes as data rates rise

11.1 The bus is a set of groups

A 64-bit bus to four ×16 chips has about 130 signals, but they fall into just a few groups with different rules. Data is split into 8-bit byte lanes. Each lane has its own strobe pair (DQS) that travels with it, so a lane only has to match itself, point to point, to one chip. Address, command and control are shared by all the chips and are clocked by the differential clock (CK). They visit each chip in turn. Pick a group to see its route and its rule:

11.2 Matching a byte lane: time, not length

The receiver samples each DQ bit on the DQS edge, which the controller places in the middle of the data eye. Every bit in the lane must therefore arrive within a small window around DQS. What matters is flight time. On an outer layer (microstrip) signals travel about 15% faster than on an inner layer (stripline), because part of the field is in air. Two traces of equal length on different layers are not matched. Drag the end of any trace to change its length, and click a signal's name to move it between layers:

Rule of thumb

Route a whole byte lane (DQ0–7, DM, DQS±) on the same layer with the same number of vias, then match lengths within the lane. Match in time (ps) whenever your tool allows it. Lanes do not need to match each other closely, because each lane has its own strobe. Bit swaps inside a lane are usually allowed, and so are whole-lane swaps: check the controller's rules, and use them to remove crossings before you start tuning lengths.

In Altium

Make one net class per byte lane (e.g. BYTE0 = DQ0–7, DM0, DQS0_P/N) and use a Matched Lengths rule on each class. Use xSignals (Design » xSignals) for paths that pass through series parts. Recent Altium versions can match in propagation delay instead of length once the Layer Stack Manager has impedance profiles; check that your version supports this, because it is what makes mixed-layer routes match correctly. Use Interactive Length Tuning (T R) to add accordions, keeping the amplitude and gap rules from lesson 8.

11.3 The address bus: fly-by, termination and write leveling

Address and command lines go to every chip. Lesson 7.3 showed that a balanced tree (T-branch) rings because each branch is an unterminated stub for the others. DDR3 and later use a fly-by chain instead: one line passes each chip through a very short stub and ends in a termination to VTT (VDDQ/2). Each chip's input capacitance loads the line, so the loaded impedance is lower than the bare trace impedance, and the termination is chosen to match the loaded value. The cost of fly-by is that each chip sees the clock and address a little later than the one before. The controller measures this during start-up (write leveling) and delays each byte lane's DQS to match.

Rule of thumb

Address/command/control: a fly-by daisy chain in the same order as the clock pair, stubs to each chip as short as possible (via straight down at the ball), termination resistors at the end of the chain with their VTT island decoupled right there. Match each address net to the clock at every chip, within the controller's limit. The flight-time difference between the first and last chip is allowed (write leveling absorbs it, up to its range); the difference between address and clock at the same chip is not.

11.4 Where the timing budget goes

Every DDR guideline is a slice of one budget: the unit interval (UI, one bit time). The DRAM needs part of it as a valid window, the controller's jitter takes part, and the layout gets what is left: skew, crosstalk-induced jitter, reflections and reference (VREF) noise. As data rates rise, the UI shrinks but the layout's contributions don't, so the rules get tighter. Change the design choices and watch the margin:

Why rules "suddenly" get strict

At DDR3-1066 the UI is 938 ps, and a 25 ps layout error is under 3% of it. At LPDDR5-6400 the UI is 156 ps, and the same 25 ps error is 16%. The physics didn't change; the budget did. That is why newer guidelines specify things that older ones ignored: same-layer routing, via-count matching, crosstalk spacing inside a lane, and reference-plane continuity.
